JianjiBox — Privacy Policy

概述

本政策说明简记药箱（JianjiBox）1.6 系列如何处理您的信息。本次依据 1.6.10 的实现核对。App 用于用药记录、库存管理、提醒及实体药盒连接，不提供诊断、处方或医疗决策；请按医嘱设置和使用。

核心用药数据默认保存在本机。我们不运营接收这些数据的开发者健康数据服务器，但您选择的 iCloud、购买与兑换、固件下载、导出分享和反馈等功能会涉及下述数据传输。因此，“本地保存”不表示所有功能均离线，也不表示任何情况下开发者都不会收到信息。

1. 在设备上处理的信息

  • 您录入的成员姓名或昵称、家庭与药箱名称、本机档案和显示视角；这些档案不是独立的联网登录账户。
  • 药名、规格、厂家、批次、有效期、库存、剂量与单位、用药时间、计划、备注、打卡和延迟记录，以及相关库存流水。
  • 您拍摄、选择或导入的药品照片，以及照片中文字或条码的识别结果。文字识别使用设备上的 Apple Vision 等系统能力，不向开发者提供云端 OCR 上传。
  • 所连接药盒的标识、名称、药仓配置、固件版本、网络名称（SSID）、局域网地址、连接状态、设备授权凭据、提醒计划与设备回执；以及主题、字号等设置和本地诊断记录。

请在有权处理相关信息的前提下添加他人的用药资料。同一设备上的成员视角不等同于独立账户的安全隔离；请妥善保护设备和备份。

2. 系统权限及拒绝权限的影响

  • 相机：拍摄药品包装或说明书、扫描条码及本地文字识别；拒绝后可手动输入信息。
  • 照片访问或系统照片选择器：读取您授权或选中的照片，用于药品记录和本地识别；授权范围取决于所用系统入口。拒绝不影响手动录入。
  • 通知：显示本地用药提醒、声音与角标；拒绝后系统提醒受限，仍可在 App 中查看记录。
  • 蓝牙：发现和连接实体药盒、配网、下发配置和提醒计划、读取状态与回执；拒绝后相应药盒功能受限。
  • 本地网络：在局域网内发现药盒、读取状态、发送受支持的命令与计划和传送固件；不用于定位。发现过程可能查询 Bonjour 服务或探测同一网段的候选地址。

1.6 不申请定位、通讯录、日历、麦克风录音、健康 App（HealthKit）或广告跟踪权限。联网本身并非单独的 iOS 权限弹窗；下文说明何时会联网。您可在系统“设置”中调整已授予的权限；撤回权限不会自动删除已有数据。

3. 手机与实体药盒

药盒功能通过蓝牙或局域网在手机与设备间交换标识、配置、提醒时间、药格/计划数据、状态及确认记录，不经开发者云端转发。配网时，App 会处理您输入或选择的 Wi-Fi 名称与密码，通过蓝牙发送给药盒；药盒在本地保存连接信息以便重连，App 也保存网络名称和连接状态等设备资料。

删除 App 或手机中的药盒记录，不等同于清除药盒内保存的 Wi-Fi、计划或记录。需要清除设备数据时，请另行使用设备提供的忘记网络或恢复出厂功能。无线传输的保护取决于系统、网络与固件实现；本政策不承诺所有本地通信均采用端到端加密。

4. 可选 iCloud 备份、设置与密钥

iCloud 备份需您启用相关功能或发起备份，默认关闭。备份可包含导出范围内的成员、药品、照片、库存、计划、打卡和设备资料；加密文件存入您自己的 iCloud Drive，自动备份仅在相应开关开启并满足条件时运行。关闭开关不会删除已有备份。

云备份在上传前使用 AES-GCM 加密；密钥存放在系统钥匙串，并使用 iCloud 钥匙串同步能力。密钥和备份的可用性受您的 Apple 账户与设备设置影响。开发者不通过该备份功能接收文件或密钥，也不提供代为恢复丢失密钥的服务；若您主动分享可解密的副本，接收方可能看到其内容。

启用相应 iCloud 设置后，主题、字号、显示选项、药箱名称及关闭状态等设置可通过 Apple 的 iCloud 键值存储同步；其中自定义名称也可能包含个人信息。这不是用药数据库的实时同步：当前 1.6.10 实现未启用 SwiftData 用药数据库的自动 CloudKit 同步。Apple 服务的数据保护适用其设置及隐私政策，不应一概视为开发者自有的端到端加密服务。

5. 内购、兑换码和会员信息

购买、验证权益及恢复购买使用 Apple StoreKit；付款资料由 Apple 处理，App 接收用于判断权益的交易和产品信息，不接收完整银行卡资料。

兑换码功能会向 Apple CloudKit 查询兑换码的哈希值，并在兑换记录中更新是否已使用、使用时间和所兑换方案等状态；这些记录使用 App 的 CloudKit 公共数据库，并非全部保存在您的私有数据库中。开发者可能通过兑换管理接触这些核销信息。会员方案、有效期、激活来源与时间等权益信息还可保存在您账户的 CloudKit 私有数据库或 iCloud 键值存储，用于恢复会员。上述会员流程不需要附带用药记录或药品照片。

6. 小组件、锁屏、实时活动与手表

为显示今日用药和进度，App 会生成本地摘要，并通过 App Group 共享容器供配套组件读取。使用桌面小组件、锁屏通知、实时活动或可用的配套手表功能时，药名、时间、剂量或进度等信息可能出现在相应屏幕上，也可能被能看到屏幕的人看到。功能可用性取决于系统和设备。

您可移除组件、调整系统通知预览，并使用 App 中可用的隐藏药名等显示选项；隐藏某个界面的内容不等于删除其底层数据。

7. 外部网络服务和网站

固件检查与下载会连接 GitHub Releases 及其下载服务；开启空闲自动升级时，满足条件后也可能自动检查或下载。设备局域网升级是手机再把文件发送给药盒。可在相关设备设置中关闭自动升级；手动检查仍会联网。这些下载请求不主动附带您的用药数据库。

购买、兑换、iCloud、用户打开的网页以及邮件反馈分别涉及 Apple、GitHub 或您选择的服务商。它们可能为提供服务处理 IP 地址、请求时间、资源路径等基础网络信息，并适用各自的隐私政策。隐私政策和帮助网站由 GitHub Pages 托管；访问网页同样会向托管方发送常规网页请求。

当前版本未集成广告 SDK、第三方行为分析或广告跟踪 SDK，不将用药数据出售或用于跨 App 广告跟踪。

8. 导出、分享和联系开发者

导出 JSON 备份或 PDF 报告、使用系统分享面板时，信息会发送到您选择的位置或接收方。JSON 可能包含较广范围的家庭和设备资料；PDF 和未加密 JSON 可被取得文件的人读取。请在分享前检查范围；本地 JSON 导出是否加密取决于您的选择，不能将所有导出都视为加密文件。

诊断和崩溃记录默认保存在本机，可能包括操作时间、错误、调用栈、药盒标识、网络地址及业务操作线索。只有您主动发送反馈、日志、截图或文件时，开发者才会收到您发送的内容，以及邮件地址等联系方式。请先检查并删除无关的健康信息和敏感内容；开发者将其用于沟通、排障和改进相关问题，不用于广告画像。

9. 保存期限、删除与撤回

本地业务记录通常保留至您主动删除、清空或删除 App。终止计划、移除成员或隐藏内容可能保留历史记录，并不一定是彻底删除。您可按 App 提供的入口查看、修改、删除、导出或恢复数据；恢复备份可能替换现有内容，请阅读确认提示。

关闭 iCloud 功能、删除本地数据或删除 App，不会自动清除 iCloud 历史备份、已分享文件、药盒数据、钥匙串内容或 Apple 购买记录。请分别在 App 的备份列表、Apple 的 iCloud 管理入口、文件接收方及实体药盒中处理对应副本。系统备份和恢复还可能受您的 Apple 设置影响。

如您曾向开发者发送个人信息，可通过下方邮箱提出访问、更正或删除请求；我们会核实请求并在适用要求下处理。依法或为处理尚未解决的问题需要保留的内容除外。

云备份还会按应用的版本数量上限自动清理较旧文件，请另行保存需要长期保留的副本。

10. 安全、未成年人和政策更新

我们使用系统沙盒、钥匙串及上述备份加密等措施降低风险，但不能承诺绝对安全。请保护设备解锁方式和 Apple 账户，只在可信设备与网络中管理用药资料。未成年人应在监护人协助下使用；为他人管理健康资料时应取得适当授权。

功能或数据处理方式变化时，我们会更新政策并标明日期；需要额外授权的功能以实际提示为准。政策说明不替代您在系统中授予或撤回的权限。

概述

本政策說明簡記藥箱（JianjiBox）1.6 系列如何處理資訊，本次依據 1.6.10 實作核對。App 提供用藥記錄、庫存、提醒及實體藥盒連接，不提供診斷、處方或醫療決策，請遵醫囑使用。

核心用藥資料預設儲存在本機。我們不營運接收這些資料的開發者健康資料伺服器，但您選用的 iCloud、購買與兌換、韌體下載、匯出分享及回饋會涉及以下傳輸。「本機儲存」不代表所有功能均離線，也不代表開發者在任何情況下都不會收到資訊。

1. 裝置上處理的資訊

包括您輸入的成員姓名或暱稱、家庭與藥箱名稱、本機檔案及顯示視角；藥名、規格、廠家、批次、效期、庫存、劑量、單位、時間、計畫、備註、打卡及延遲記錄和庫存流水；您拍攝、選取或匯入的照片及辨識結果；藥盒標識、名稱、藥倉設定、韌體、網路名稱（SSID）、區域網路位址、狀態、授權憑據與回執，以及偏好設定和本機診斷記錄。

文字或條碼辨識使用裝置上的 Apple Vision 等系統能力，不上傳至開發者的雲端 OCR。請在有權處理他人資料時才新增。同機成員檔案不是獨立的網路登入帳戶，也不等同獨立帳戶的安全隔離；請保護裝置及備份。

2. 系統權限

  • 相機：拍攝藥品或說明書、掃描條碼及本機文字辨識；拒絕後可手動輸入。
  • 照片或系統照片選擇器：讀取您授權或選取的照片，用於記錄及辨識；範圍依系統入口而定。
  • 通知：本機用藥提醒、聲音與角標；拒絕後系統提醒受限，仍可查看 App。
  • 藍牙：搜尋、連接及設定藥盒、配網、傳送提醒計畫和讀取回執。
  • 區域網路：透過 Bonjour 或同網段候選位址探測尋找藥盒，讀取狀態、傳送支援的命令、計畫及韌體；不用於定位。

拒絕藍牙或區域網路權限會限制相關藥盒功能。1.6 不申請定位、聯絡人、行事曆、麥克風錄音、HealthKit 或廣告追蹤權限。網路連線本身不是獨立的 iOS 權限彈窗。可在系統設定調整權限；撤回不會自動刪除既有資料。

3. 手機與實體藥盒

手機與藥盒透過藍牙或區域網路直接交換標識、設定、提醒時間、藥格與計畫、狀態及確認記錄，不經開發者雲端轉送。配網時 App 處理您輸入或選取的 Wi-Fi 名稱與密碼，透過藍牙傳給藥盒；藥盒在本機保存連線資料以便重連，App 亦保存網路名稱及狀態等裝置資料。

刪除 App 或手機的藥盒記錄不會自動清除藥盒內的 Wi-Fi、計畫及記錄，請另行使用忘記網路或恢復出廠功能。無線傳輸保護依系統、網路和韌體而定，不承諾所有本機通訊均端到端加密。

4. 可選 iCloud 備份、設定與密鑰

iCloud 備份預設關閉，需啟用相關功能或主動發起；可包含匯出範圍內的成員、藥品、照片、庫存、計畫、打卡和裝置資料。檔案在上傳前以 AES-GCM 加密後存入您自己的 iCloud Drive；自動備份依開關及執行條件運作，關閉不會刪除舊備份。

密鑰儲存於系統鑰匙圈並使用 iCloud 鑰匙圈同步，其可用性受 Apple 帳戶及裝置設定影響。開發者不透過此功能接收備份或密鑰，也不提供遺失密鑰的代復原；主動分享可解密副本時，接收者可能讀取內容。

啟用相應 iCloud 設定後，主題、字級、顯示選項、藥箱名稱及關閉狀態等可透過 Apple 鍵值儲存同步，自訂名稱也可能包含個人資訊。這不是用藥資料庫的即時同步：目前 1.6.10 未啟用 SwiftData 用藥資料庫的自動 CloudKit 同步。Apple 的資料保護依其設定及政策，不應一概視為開發者自有的端到端加密服務。

5. 購買、兌換與會員

購買、權益驗證與恢復使用 Apple StoreKit；付款資訊由 Apple 處理，App 接收判斷權益所需的交易和產品資訊，不接收完整信用卡資料。

兌換碼會向 Apple CloudKit 查詢雜湊值，並更新已使用狀態、時間及方案；這些記錄位於 App 的 CloudKit 公共資料庫，不全在您的私有資料庫，開發者可能透過管理接觸核銷資訊。會員方案、有效期、來源與啟用時間等亦可存於您帳戶的私有資料庫或 iCloud 鍵值儲存以恢復權益，不需要附帶用藥記錄或照片。

6. 小工具、鎖定畫面、即時動態與手錶

App 生成今日用藥及進度的本機摘要，透過 App Group 共享容器供配套元件讀取。使用小工具、鎖定畫面通知、即時動態或可用的手錶功能時，藥名、時間、劑量及進度可能出現在螢幕，被旁人看到；可用性依系統和裝置而定。

可移除元件、調整系統預覽及使用 App 可用的隱藏藥名選項。隱藏顯示不代表刪除資料。

7. 外部服務與網站

韌體檢查與下載會連接 GitHub Releases 及下載服務；開啟閒置自動升級時，符合條件後也可能自動檢查或下載，再由手機將檔案傳給藥盒。可在裝置設定關閉自動升級，手動檢查仍會連線。下載請求不主動附帶用藥資料庫。

購買、兌換、iCloud、開啟網頁及郵件回饋會涉及 Apple、GitHub 或您選擇的服務商，它們可能處理 IP、請求時間與資源路徑等基本網路資訊，適用各自政策。隱私及說明網站由 GitHub Pages 託管，瀏覽會向託管方發送一般網頁請求。目前未整合廣告、第三方行為分析或廣告追蹤 SDK，不出售用藥資料或用於跨 App 廣告追蹤。

8. 匯出、分享及回饋

JSON 備份、PDF 報告或系統分享會送至您選擇的目的地。JSON 可能包含較廣的家庭及裝置資料；PDF 和未加密 JSON 可由取得檔案者讀取。本機 JSON 加密依您的選擇，請分享前核對範圍。

診斷與崩潰記錄預設僅在本機，可能有時間、錯誤、呼叫堆疊、裝置標識、網路位址及業務操作線索。只有您主動傳送回饋、日誌、截圖或檔案時，開發者才收到內容及電郵等聯絡資訊，用於溝通、排障和改進問題，不作廣告畫像。請先刪除無關的健康及敏感資訊。

9. 保留、刪除及撤回

本機記錄通常保留至您刪除、清空或刪除 App。終止計畫、移除成員或隱藏內容可能保留歷史，並非徹底刪除。可透過 App 提供的入口查看、修改、刪除、匯出或恢復；恢復備份可能替換既有內容。

關閉 iCloud、清除本機或刪除 App 不會自動清除 iCloud 舊備份、分享檔案、藥盒資料、鑰匙圈或 Apple 購買記錄。請分別在備份清單、Apple iCloud 管理、接收方和藥盒處理副本；系統備份和恢復也依 Apple 設定。曾向開發者發送個人資訊時，可聯絡下方郵箱要求存取、更正或刪除；經核實依適用要求處理，依法或處理未結問題所需保留者除外。

Overview

This policy describes information handling in JianjiBox 1.6, reviewed against implementation 1.6.10. The app provides medication records, inventory, reminders and physical pillbox connections, not diagnosis, prescriptions or medical decisions. Follow your clinician’s instructions.

Core medication data is stored on your device by default. We do not operate a developer health-data server receiving it. However, optional iCloud, purchases and redemption, firmware downloads, exports, sharing and support involve the transfers described below. Local storage does not mean every feature is offline or that the developer can never receive information.

1. Information processed on your device

This includes member names or nicknames, family and box names, local profiles and display viewpoints; medication names, specifications, manufacturers, batches, expiry, stock, doses, units, schedules, notes, check-ins, deferrals and inventory history; photos you take, select or import and their recognized text or barcodes; pillbox identifiers, names, compartment configuration, firmware, Wi-Fi names (SSID), LAN addresses, status, device authorization credentials, plans and receipts; preferences and local diagnostic records.

Recognition uses on-device Apple Vision and related system capabilities, not a developer cloud OCR upload. Enter another person’s health information only with appropriate authority. Local member profiles are not separate online login accounts or equivalent security isolation; protect your device and backups.

2. System permissions

  • Camera: medicine or leaflet photos, barcode scanning and local recognition; manual entry remains available if denied.
  • Photos or the system picker: reads photos you authorize or select for records and recognition; scope depends on the system entry point.
  • Notifications: local reminders, sound and badges; denial limits system alerts, not viewing app records.
  • Bluetooth: discovers, connects and configures the pillbox, provisions Wi-Fi, sends plans and reads status or receipts.
  • Local network: finds pillboxes using Bonjour or probes of candidate addresses on the same subnet, reads status and sends supported commands, plans and firmware; it is not used for location tracking.

Denying Bluetooth or LAN permission limits the related hardware features. Version 1.6 does not request location, contacts, calendar, microphone recording, HealthKit or advertising tracking permissions. Internet access is not a separate iOS permission prompt. You can change permissions in system Settings; revocation does not automatically delete existing data.

3. Phone and physical pillbox

The phone exchanges identifiers, settings, reminder times, compartment/plan data, status and confirmations directly with the pillbox over Bluetooth or LAN, without a developer cloud relay. During Wi-Fi setup, the app processes the network name and password you supply and sends them over Bluetooth. The pillbox saves connection information locally for reconnection; the app also retains network names, connection status and other device details.

Deleting the app or its pillbox entry does not clear Wi-Fi, plans or records inside the hardware. Use its forget-network or factory-reset feature separately. Wireless protection depends on the system, network and firmware; we do not claim all local communications are end-to-end encrypted.

4. Optional iCloud backups, settings and keys

iCloud backup is off by default and requires enabling the relevant feature or initiating a backup. It can contain members, medication, photos, inventory, plans, check-ins and device details within the export scope. Files are AES-GCM encrypted before upload to your iCloud Drive. Automatic backup depends on its switches and operating conditions; switching it off leaves existing backups intact.

The encryption key is stored in system Keychain using iCloud Keychain synchronization. Availability depends on your Apple account and device settings. The developer does not receive backup files or keys through this feature and cannot recover a lost key for you. A recipient of a decryptable copy you share may read its contents.

When the corresponding iCloud setting is enabled, preferences such as theme, text size, display options, box names and closed-box status can sync through Apple’s key-value storage. Custom names may themselves contain personal information. This is not live medication-database synchronization: implementation 1.6.10 does not enable automatic SwiftData medication-database CloudKit sync. Apple’s protection depends on its settings and policies; it should not be described as universally developer-controlled end-to-end encryption.

5. Purchases, codes and membership

Purchases, entitlement verification and restoration use Apple StoreKit. Apple handles payment information; the app receives transaction and product information needed for entitlements, not full payment-card details.

Code redemption queries a code hash in Apple CloudKit and updates used status, redemption time and plan. These records use the app’s CloudKit public database, not exclusively your private database. The developer may access redemption-management metadata. Membership plan, expiry, activation source and time may also be stored in your account’s private CloudKit database or iCloud key-value storage for restoration. These membership flows do not require medication records or photos.

6. Widgets, lock screen, Live Activities and Watch

The app generates local medication/progress summaries and shares them with companion components through an App Group container. Widgets, lock-screen notifications, Live Activities or available companion Watch features may display medicine names, times, doses or progress to people who can see the screen. Availability depends on the system and device.

You can remove components, change notification previews and use available medicine-name hiding options. Hiding a display does not delete the underlying records.

7. External services and website

Firmware checks and downloads contact GitHub Releases and its download services. Idle automatic upgrades may check or download when enabled and conditions permit, after which the phone sends the file to the pillbox locally. You can disable automatic upgrades in the relevant device settings; manual checks still access the network. Download requests do not intentionally attach your medication database.

Purchases, redemption, iCloud, webpages and email feedback involve Apple, GitHub or services you choose. Providers may process IP addresses, request times, resource paths and other basic network information under their policies. The privacy and help website is hosted on GitHub Pages; visits send ordinary web requests to the host. The current version has no advertising, third-party behavioral analytics or advertising-tracking SDKs, and does not sell medication data or use it for cross-app advertising tracking.

8. Exports, sharing and support

JSON backups, PDF reports and system sharing go to destinations or recipients you select. JSON may include a broad range of family and device records; anyone obtaining a PDF or unencrypted JSON can read it. Local JSON encryption depends on your choice. Review the export scope before sharing.

Diagnostic/crash records stay locally by default and may include times, errors, stack traces, device identifiers, network addresses and operational context. If you choose to send feedback, logs, screenshots or files, the developer receives their contents and contact details such as your email address for communication, troubleshooting and resolving the issue, not advertising profiling. Remove unrelated health and sensitive information before sending.

9. Retention, deletion and withdrawal

Local records are generally kept until you delete or clear them or delete the app. Ending a plan, removing a member or hiding content may retain history and is not necessarily permanent deletion. App features let you view, change, delete, export or restore records; restoration can replace existing content, so read the confirmation.

Turning off iCloud or deleting local data or the app does not automatically remove earlier iCloud backups, shared files, hardware records, Keychain items or Apple purchase history. Manage copies separately in the backup list, Apple iCloud settings, recipient locations and pillbox. System backup/restore also depends on Apple settings. If you sent personal information to the developer, contact us below for access, correction or deletion; verified requests are handled under applicable requirements, subject to legally required retention or unresolved support matters.

Cloud backup also removes older files when its version-count limit is exceeded. Keep a separate copy if you need long-term retention.

10. Security, children and changes

We use system sandboxing, Keychain and the backup encryption described above, but cannot guarantee absolute security. Protect device unlocking and your Apple account and use trusted devices and networks. Minors should use the app with guardian assistance; obtain appropriate authority to manage others’ health information. We update this policy and its date when practices change. Features requiring additional authorization use their actual prompts; this policy does not replace system permission choices.

本ポリシーは JianjiBox 1.6シリーズの情報の取扱いを説明し、1.6.10の実装を確認して作成しています。本アプリは服薬記録、在庫管理、通知、薬ケース接続のためのもので、診断、処方、医療判断を提供しません。医療従事者の指示に従ってください。

主な服薬データは初期設定で端末内に保存され、開発者はこれを受信する健康データ用サーバーを運営していません。ただし、任意のiCloud機能、購入・コード利用、ファームウェア取得、書き出し・共有、問い合わせでは以下の通信が生じます。端末保存は、全機能がオフラインであることや、開発者が一切情報を受け取らないことを意味しません。

1. 端末内で処理する情報

入力したメンバーの氏名・ニックネーム、家族・薬箱名、ローカルプロフィールと表示視点、薬名・規格・メーカー・ロット・使用期限・在庫・用量・単位・時刻・計画・メモ・服薬確認・延期履歴と在庫履歴、撮影・選択・読み込みした写真と認識結果、薬ケースの識別子・名称・構成・ファームウェア・Wi-Fi名（SSID）・LANアドレス・状態・認証情報・計画・応答、設定および端末内の診断記録を処理します。

文字・バーコード認識はApple Vision等によって端末上で行い、開発者のクラウドOCRには送信しません。他人の健康情報は適切な権限を得て入力してください。同一端末のプロフィールは独立したオンラインアカウントや同等の安全な分離ではありません。端末とバックアップを保護してください。

2. システム権限

  • カメラ：薬や説明書の撮影、バーコードと文字の端末内認識。拒否しても手入力できます。
  • 写真・システム選択画面：許可または選択した写真を記録・認識に利用します。範囲はシステムの入口によります。
  • 通知：ローカルの服薬通知、音、バッジ。拒否すると通知は制限されますが、アプリ内の記録は閲覧できます。
  • Bluetooth：薬ケースの検出・接続・設定、Wi-Fi設定、計画送信と状態・応答の取得。
  • ローカルネットワーク：Bonjourや同一サブネットの候補アドレスへの照会による検出、状態取得、対応コマンド・計画・ファームウェアの送信。位置追跡には使用しません。

Bluetooth・LAN権限を拒否すると関連機能が制限されます。1.6は位置、連絡先、カレンダー、マイク録音、HealthKit、広告追跡の権限を要求しません。インターネット接続自体は独立したiOS権限ダイアログではありません。権限はシステム設定で変更でき、撤回しても既存データは自動削除されません。

3. スマートフォンと薬ケース

識別情報、設定、通知時刻、区画・計画、状態、確認記録をBluetoothまたはLANで直接交換し、開発者のクラウドを中継しません。Wi-Fi設定時には入力・選択したネットワーク名とパスワードを処理してBluetoothで薬ケースへ送信します。薬ケースは再接続用情報を本体に保存し、アプリもネットワーク名や状態などを保持します。

アプリや端末上の薬ケース登録の削除では、機器内のWi-Fi・計画・記録は消えません。ネットワーク削除や初期化を別途行ってください。無線通信の保護はシステム・ネットワーク・ファームウェアに依存し、すべてがエンドツーエンド暗号化されるとは保証しません。

4. 任意のiCloudバックアップ・設定・鍵

iCloudバックアップは初期状態で無効で、機能の有効化または操作が必要です。書き出し範囲のメンバー、薬、写真、在庫、計画、確認記録、機器情報を含む場合があります。ファイルは送信前にAES-GCMで暗号化して利用者のiCloud Driveに保存します。自動実行はスイッチと条件に従い、無効にしても既存ファイルは消えません。

鍵はシステムKeychainに保存し、iCloudキーチェーン同期を利用します。利用可能性はAppleアカウントと端末設定によります。この機能から開発者がファイルや鍵を受け取ることはなく、紛失した鍵の代理復旧も提供しません。復号可能なコピーを自ら共有した場合、受取人が読める可能性があります。

該当iCloud設定を有効にすると、テーマ、文字サイズ、表示設定、薬箱名や終了状態などがAppleのキー値ストレージで同期されます。自由入力の名称には個人情報が含まれ得ます。これは服薬データベースのリアルタイム同期ではなく、1.6.10ではSwiftDataの自動CloudKit同期は有効ではありません。Appleの保護は同社の設定・ポリシーに依存し、一律に開発者独自のエンドツーエンド暗号化とはいえません。

5. 購入・コード・会員情報

購入、権利確認、復元はApple StoreKitを利用します。支払い情報はAppleが処理し、アプリは権利判定に必要な取引・製品情報を受け取りますが、カード情報全体は受け取りません。

コード利用ではApple CloudKitにハッシュ値を照会し、利用済み状態、日時、プランを更新します。これはアプリのCloudKit公開データベースを使うため、すべてが利用者の非公開データベースに保存されるわけではなく、開発者が管理上その利用情報に接することがあります。プラン・期限・有効化元・日時などは復元用に利用者の非公開CloudKitやiCloudキー値ストレージにも保存され得ます。この処理に服薬記録や写真は必要ありません。

アプリは当日の服薬・進捗のローカル要約をApp Group共有領域に保存して関連コンポーネントから参照します。ウィジェット、通知、ライブアクティビティや利用可能なWatch機能では、薬名・時刻・用量・進捗が画面に表示され、周囲の人にも見えることがあります。利用可否はシステムと機器に依存します。

コンポーネントの削除、通知プレビュー設定、アプリにある薬名非表示設定などを利用できます。非表示はデータ削除ではありません。

ファームウェア確認・取得はGitHub Releasesと配信サービスに接続します。アイドル時の自動更新を有効にすると、条件に応じて自動確認・取得し、その後端末から薬ケースへ送信します。機器設定で自動更新を無効にできますが、手動確認も通信します。取得要求に服薬データベースを意図的に添付しません。

購入・コード・iCloud・ウェブ閲覧・メールにはApple、GitHubや選択した事業者が関与し、IP、要求時刻、リソースパスなど通常の接続情報を各社の方針で処理する場合があります。プライバシー・ヘルプサイトはGitHub Pagesで配信し、閲覧も通常のウェブ要求を送信します。現在、広告・第三者行動分析・広告追跡SDKは導入せず、服薬データの販売やアプリ横断広告追跡には利用しません。
